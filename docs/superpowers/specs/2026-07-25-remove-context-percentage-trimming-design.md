# 删除 context 百分比裁剪机制

## 范围

完整删除插件根据总 context 的 25%、40%、60% 或自定义聊天预算来判断是否裁剪请求的机制。插件不再估算最终请求是否能容纳聊天，也不再修改 SillyTavern 交给生成拦截器的聊天数组。

本次不设计或实现新的剧情摘要注入策略。每轮总结、章节总结和卷总结继续生成、保存、查看并参与既有重建流程，但 L2 暂时不发送，直到用户另行确定明确的注入规则。L1 当前事实和显式开启的 L4 相关旧记忆保持现状。

## 删除内容

- 删除生成拦截器及 manifest 中的 `generate_interceptor` 注册。
- 删除聊天 token 计数、context 百分比、自定义聊天预算、安全裁剪边界和请求数组 `splice` 逻辑。
- 删除 `historyBudgetMode`、`historyTokenBudget`、`minRecentPairs`、`recentPairs` 的默认值、迁移和设置界面。
- 删除 `context_handoff` 运行时诊断、发送预览中的裁剪范围及相关文案。
- 删除仅验证裁剪行为的测试，并增加静态契约测试，禁止百分比设置、生成拦截器和请求数组裁剪代码返回。

旧聊天 metadata 或 settings 中已经保存的同名字段不主动清洗；新代码不读取它们，避免为了删除运行机制而改写用户数据。

## 未采用方案

- 只删除百分比、保留自定义 token：插件仍然在看不完整最终请求的阶段做预算决策，不符合要求。
- 立即改成始终注入全部摘要：这是新的产品行为，超出本次“只删除错误机制”的范围。

## 验证

- 仓库运行时代码中不存在百分比预算、聊天裁剪器、`context_handoff` 或生成拦截器。
- 设置界面不再显示聊天历史容量、百分比模式或最近保留轮数。
- L1 仍为 `IN_PROMPT`，L4 仍为显式开关；L2 注册为空内容。
- 完整测试通过，工作区提交后直接推送 `main`。
