# SillyTavern 主线程性能修复设计

## 目标

让长聊天中的滚动、菜单和普通点击保持即时响应。所有修复只改变前端运行机制，不读取、删除或重写聊天、角色、备份或记忆数据。

## 已确认的问题

1. 幕间 UI 永久观察整个 `document.body`；任意 DOM 变化都会安排一次完整聊天楼层扫描。
2. Chat Search 在聊天选择弹窗尚未找到时退化为永久观察整个 `document.body`。
3. 酒馆自定义流式动画在每次流式更新时读取布局并启动动画；滚动处理也会在每次事件中同步读取布局。

## 设计

### 幕间

- 删除永久 `MutationObserver`。
- 删除 AI 正文操作区中的幕间回看图标。
- 只保留可点击的“幕间讨论”控制楼。
- 聊天载入时执行一次控制楼标记恢复；新建控制楼时只处理对应楼层。
- 生成、停止和聊天切换状态通过 SillyTavern 事件显式刷新按钮，不再推测 DOM 变化。
- 幕间按钮宿主尚未出现时使用有次数上限的短暂重试，不观察整个页面。

### Chat Search

- 只观察静态页面中真实存在的 `#select_chat_popup` 或 `#shadow_select_chat_popup`。
- 两者都不存在时直接跳过，不允许回退到 `document.body`。

### 酒馆滚动与流式更新

- 粗指针设备和“减少动态效果”设备不执行逐 token 高度测量与文字动画，只更新正文。
- 滚动状态计算通过 `requestAnimationFrame` 合并，同一帧最多执行一次。
- 保留最终消息入场、自动滚动和跨设备同步功能。

## 验收

- 幕间源码中不存在 `MutationObserver`、回看图标创建逻辑或 DOM 变化触发的全聊天扫描；显式刷新可以移除旧版本遗留图标。
- Chat Search 不再观察 `document.body`。
- 移动端流式路径不读取旧正文高度或创建逐 token 动画。
- 滚动回调同一帧最多计算一次底部位置。
- 插件完整测试通过；线上代码语法检查、HTTP 存活检查和实际部署版本检查通过。
