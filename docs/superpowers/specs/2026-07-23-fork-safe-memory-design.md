# Fork 安全的分支记忆设计

## 目标

用户在任意旧消息处创建 SillyTavern 分支后，新分支只继承分叉点以前成立的记忆，父分支和子分支随后独立演化。恢复未完成或失败时不得注入可能串线的记忆。

## 已确认的宿主行为

SillyTavern 创建分支时复制分叉点以前的消息，只给新聊天写入 `main_chat` 父聊天名，不复制第三方扩展的聊天元数据。新聊天加载完整消息和元数据后触发 `CHAT_CHANGED`。消息 `extra` 中的 `layered_memory_id` 会随消息快照保留。

## 数据模型

- `floor_events`：每轮提取后的不可变事件，包含稳定 `floorKey`、正文指纹、轮次、完整的受影响条目终态和每轮摘要。相同楼层重新生成时替换该楼层事件。
- `manual_events`：用户增删改、固定记忆和批准校对建议时产生的小型事件，绑定当时最后一轮对话及其正文指纹。
- `branch_checkpoints`：不含 changelog 的轻量状态表检查点，绑定创建时最后一条已封存对话的稳定 `floorKey` 和正文指纹。首次升级、旧聊天补记完成及分支恢复后生成，分支恢复链最多保留所需的最早与最新检查点。
- `branch_origin`：记录父聊天、恢复方式、分叉点和恢复时间，供诊断显示。

检查点解决升级前已有状态；楼层事件和手动事件负责从最近可用检查点确定性重放后续变化。状态表自动整理是派生优化，不生成整表快照，避免长聊天的档案体积平方增长。

## 分支恢复

1. `CHAT_CHANGED` 后，如果当前聊天带 `main_chat` 且没有插件数据，进入恢复屏障。
2. 通过 SillyTavern `/api/chats/get` 或 `/api/chats/group/get` 读取父聊天头部的插件元数据。
3. 用新分支实际包含的稳定消息 ID 与用户/AI 正文计算有效 `floorKey + contentFingerprint`。只相同 ID 不足以证明是同一条 swipe。
4. 选择锚点和正文指纹都匹配的最新检查点，从该状态开始，按发生顺序重放仍位于连续可信前缀内的楼层事件和手动事件。首个正文指纹不匹配楼及其后内容一律不复用。
5. 每轮摘要按 `floorKey` 过滤；只复用完整落在分支范围内的章节；卷摘要只有在其全部章节都保留时才复用，否则重新排队生成。
6. 待确认项只保留仍存在楼层产生的项目。后台队列一律清空并生成新的 `scope_id`。
7. 父数据只读，新分支保存独立副本。

若没有可验证的检查点（例如旧版档案或分叉点早于首个检查点），不得复制父状态或依赖可能被截断的旧 changelog。新分支从空状态开始，以 `safe_rebuild` 模式重新整理这个分支自己的聊天历史；重建完成前不会注入父分支的旧记忆。

## 生成屏障与失败处理

- 初始化、`CHAT_CHANGED`、消息事件和生成拦截器共享同一个恢复 Promise。
- 恢复完成前不更新注入；生成拦截器等待恢复结束。
- 父聊天读取或保存失败时，清空新分支注入，写入显眼的恢复失败提示，不用父分支当前记忆继续生成。
- 重复进入已经恢复的分支必须幂等，不再次复制或重放。

## 验收矩阵

- 单聊与群聊。
- 从用户消息、AI 回复、章节中间创建分支。
- 从非当前 swipe 创建分支，消息 ID 相同但正文不同。
- 分支点位于检查点之前和之后。
- Fork 时任务正在运行或等待重试。
- 连续 Fork，父子分支来回切换，父分支之后继续产生新记忆。
- 恢复期间立即发送消息。
- 父聊天缺失、接口失败和保存失败时必须 fail closed。
