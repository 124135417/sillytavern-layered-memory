# 记忆模型成本与余额故障收敛设计

## 目标

降低分层记忆插件调用 DeepSeek V4 Flash 时不必要的推理输出成本，并让真实 token、缓存命中和费用估算可见。账户余额不足时，第一条 HTTP 402 应立即暂停该聊天的后台队列并保留工作，避免其余任务继续失败。

本改动只作用于插件自己的辅助记忆模型请求，不修改 SillyTavern 主聊天模型、预设或其它连接。

## 已确认的故障链

1. 官方 DeepSeek V4 API 当前默认开启思考模式，而插件的直连请求没有显式关闭它。
2. 插件只读取 `choices[0].message.content`，丢弃响应中的 `usage`、缓存 token 和 reasoning token，页面无法解释真实消耗。
3. 队列把 HTTP 402 当作可重试错误；同一任务最多重试三次，队列中的其它任务仍会继续领取，余额耗尽后会形成大面积失败和保存压力。

## 方案选择

采用“关闭默认思考 + 用量账本 + 402 熔断”的组合方案。

- 仅关闭思考：改动小，但依然无法解释费用，余额不足时仍会冲击整个队列。
- 自动切换其它模型：能暂时继续处理，但会静默改变模型、价格和输出质量，违反插件现有的独占路由约定。
- 组合方案：降低非必要输出，保留真实用量证据，并在不可恢复的账户故障处停止扩散；不做静默兜底。

## 请求行为

- 当直连地址的规范化主机名为 `api.deepseek.com` 时，聊天补全请求和连接测试都显式发送 `thinking: { type: "disabled" }`。
- 其它 OpenAI 兼容地址不发送 DeepSeek 专用字段。
- JSON 输出继续沿用官方 DeepSeek 的 `json_object` 模式；非 DeepSeek 地址继续使用现有 `json_schema` 格式。
- 主聊天连接、Connection Manager profile 路径及 current connection 路径均不增加 DeepSeek 专用字段。

## 用量账本与显示

每次成功的直连辅助模型请求把以下信息追加到全局扩展设置中的有界账本：

- 时间、用途、路由和模型；
- prompt、completion、total token；
- prompt cache hit、prompt cache miss token；
- reasoning token；
- 若且仅若模型为 `deepseek-v4-flash` 且服务地址为官方 DeepSeek，按 2026-08-09 的公开价格快照计算人民币估算值，并同时保存价格版本。

账本最多保留最近 500 条，避免设置无限增长。设置页显示最近记录的请求数、总 token、缓存命中率、reasoning token 与估算费用。费用必须标为估算，不能伪装成服务商账单；缺少 usage 的响应不写入伪造数据。

## HTTP 402 熔断

- HTTP 402 是不可重试错误。
- 任一运行中任务收到 402 后，将自身放回等待队列，不增加下一次继续时的尝试次数；不进入失败列表。
- 同一聊天队列立即设为暂停，并写入结构化的 `pause_reason`：类别 `balance`、安全的用户提示和时间。
- 已经并行发出的其它请求允许自然收尾；若它们也收到 402，同样保留为等待任务，不产生重复项。
- 暂停后不再领取新任务。用户充值后点击“继续”，清除 `pause_reason` 并恢复队列。
- 页面顶部直接显示“记忆模型余额不足，后台整理已暂停”，而不是对每个任务重复显示泛化错误。
- 连接测试把 402 分类为 `balance`，提示充值后继续。

## 数据兼容与安全

- `usageHistory` 是带默认空数组的新增全局设置，旧设置自动补齐。
- `pause_reason` 是聊天队列状态的可选字段，旧聊天默认为空。
- 账本不保存 API 密钥、提示词、模型回复或服务商原始错误体。
- 不自动充值、不自动改路由、不自动重放主聊天请求。

## 验收

- 官方 DeepSeek 直连请求和连接测试均带 `thinking.disabled`；其它地址不带该字段。
- 成功响应的 usage 被规范化并持久化，设置页汇总计算正确；无 usage 响应保持兼容。
- HTTP 402 不进入普通重试，第一条 402 后队列暂停、任务保留、后续任务不启动；手动继续可恢复处理。
- 连接测试对 402 显示余额不足分类。
- 现有路由、队列并发、UI smoke 与完整测试套件全部通过。

## 部署与回滚

版本升至 0.16.7，推送后让线上插件目录快进到该提交，并通过静态资源、浏览器实际请求体和队列 UI 验证。若出现回归，回退这一实现提交即可；新增设置字段和队列字段均为向后兼容的可选数据。
