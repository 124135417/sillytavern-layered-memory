# 幕间叙述者设计

## 目标

在 SillyTavern 输入区旁增加一个“幕间”入口。玩家可以暂停剧情，与刚才的同一个叙述者直接讨论剧情、询问连续性或调整下一段走向；讨论结束后，由叙述者立即生成下一层正文。整个过程不要求玩家选择卡片、期限或结构化选项。

## 核心体验

1. 玩家点击输入区旁的面具按钮，幕间窗口外壳必须在下一次浏览器绘制时出现；会话恢复、数据归一化、状态克隆、token 估算和历史渲染都在外壳首次绘制后进行。
2. 幕间使用当前主模型和当前连接，但不运行正文预设、角色卡、世界书、作者注释、对话示例或酒馆原生 Chat History。它只接收插件已经整理好的前文剧情摘要、最近完整正文、本次幕间对话和一条幕间系统指令。
3. 玩家和叙述者自然对话。关闭窗口只保存草稿，不触发正文。
4. 玩家点击“可以了，继续！”，插件把完整幕间对话包装成一条玩家输入，要求模型从暂停处直接继续剧情。
5. 主聊天只显示紧凑的“幕间讨论”标记；完整输入保存在该消息中，可点击重新查看，但不会作为剧情正文进入插件的摘要和事实来源。
6. 生成结果是新的 assistant 楼层。该楼层的全部 swipe 使用同一版幕间输入。
7. 如果结果不满意，玩家从该回复的消息操作中点击“回到幕间”，继续告诉叙述者哪里不对；再次生成时更新幕间输入，并创建同一 assistant 楼层的新 swipe。
8. 玩家可以随时点击“清空本次幕间”，立即终止当前幕间请求、清除尚未采用的讨论和输入草稿，并从空白幕间重新开始。

## 数据与隔离

- 每个聊天在 `chatMetadata.layered_memory.backstage` 下保存幕间会话、工作草稿和不可变的生成版本。
- 每个版本保存当时的完整幕间消息、被否决的正文草稿和目标 swipe 的引用。
- 幕间玩家消息通过 `extra.layered_memory_backstage_marker` 标识，assistant 候选通过 `extra.layered_memory_backstage` 记录会话和版本；SillyTavern 的 `swipe_info.extra` 保留每个候选的来源。
- 点击“可以了，继续！”后，幕间全文是下一次正文生成的真实玩家输入，因此由酒馆按正常 token 预算处理；插件不静默截断或自动总结。
- 插件的剧情正文、近期原文、事实提取和时间证据把幕间玩家楼视为没有剧情正文。生成出的 assistant 正文仍照常进入逐楼摘要和事实提取。
- 会话跟随聊天元数据和分支复制；切换聊天、分支或 swipe 时不得串用其它会话的工作草稿。

## 幕间讨论请求的上下文边界

幕间讨论不再调用 SillyTavern 的 `Generate('quiet')`。它使用当前连接和模型的原始生成接口，并显式构造以下内容：

1. 固定且简短的幕间 system 指令；
2. `buildCoreMemoryParts()` 生成的 `l2`，即前面的逐楼/章节/长期剧情摘要；
3. 同一函数生成的 `raw`，即当前设置预算内最近连续完整正文；
4. 本次幕间消息，按真实 user/assistant 角色交替发送。

明确不发送 `l1` 当前事实表、`l4` 关键词召回、正文预设、角色卡、世界书、作者注释、对话示例、工具定义、正文格式提示和原生 Chat History。插件自身对 `l2 + raw` 的覆盖范围、正文提取、HTML 注释清理、文风重置边界和 token 预算继续作为唯一剧情来源，不另造一套摘要或截断规则。

幕间回复的最大输出长度固定为 768 token。幕间窗口必须明确显示“叙述者正在回应”，不把无流式增量误呈现成未发送。

## 即时反馈与单次提交

- 打开：点击入口后的第一个有意义操作是显示不依赖聊天数据的原生 `dialog` 外壳。外壳显示前不得调用 `getChatData()`、恢复会话、克隆状态、估算 token 或渲染历史。
- 首帧：外壳立即进入可见状态，显示“正在接上这段剧情…”，设置 `aria-busy="true"`，并暂时禁用输入。必须先把控制权交还浏览器完成一次绘制，再在后续任务中建立或恢复会话。
- 就绪：会话恢复后先渲染标题、历史与输入草稿并解除 busy；token 估算排到内容之后，不能再次阻塞窗口或输入可用。聊天切换后可以在浏览器空闲时预热数据，但预热不得成为打开窗口的前置条件。
- 恢复失败：窗口不能消失或长时间停在无说明状态；在已经出现的外壳内显示可关闭、可重试的错误。
- 发送：第一次点击必须在任何 `await` 之前同步取得单次提交锁、捕获并清空输入、追加唯一的玩家消息并渲染等待状态。
- 同一个玩家消息只能有一个活动模型请求。鼠标连点、触屏重复触发和 Enter 重复事件都只复用或忽略当前请求，不能追加重复消息或启动并发请求。
- 元数据保存继续按顺序串行，但不阻塞模型调用。模型回复进入内存后立即渲染，再排队持久化。
- 模型失败时保留唯一的玩家消息并解除提交锁；“重新询问”复用该消息，不再追加一份。
- 点击“可以了，继续！”也使用同样的同步锁和即时状态，持久化不能推迟正文请求的开始。
- 每个请求带会话内的唯一请求标识和代次。清空、切换聊天或重新开始会让旧代次失效；迟到的旧结果不得重新写回界面或元数据。

## 清空语义

“清空本次幕间”只作用于当前工作副本：

- 同步清除当前幕间消息、输入草稿和未采用正文草稿；
- 调用停止接口终止所有仍在运行的幕间请求，并递增请求代次；
- 立即恢复空白输入状态，然后在后台保存；
- 不删除已经生成的主聊天正文、旧 swipe、已归档幕间版本或插件剧情记忆。

清空后关闭再打开仍然为空。清空之前已经发出的请求即使随后返回，也必须因为请求代次不匹配而被丢弃。

## 生成生命周期

- 首次继续：把幕间全文放入输入框请求，走 SillyTavern 普通生成；`MESSAGE_SENT` 发生时补上紧凑显示和会话来源。
- 重写：修改原幕间玩家消息，建立新版本，把当前 assistant 置为下一 swipe 槽，再走 `Generate('swipe')`。
- 普通右滑生成：如果当前 assistant 来源于幕间，沿用其当前幕间版本。
- 取消、停止、网络错误或刷新不会删除工作草稿。只有成功保存 assistant 候选后，版本才标记为已生成。
- 玩家发送后续普通正文输入后，本次会话归档；历史标记仍可查看，但不能从旧楼层直接改写已经继续发展的故事。

## 幕间模型提示

幕间回复要求模型：

- 作为刚才的同一个叙述者说话，而不是独立顾问或剧情角色；
- 暂停剧情，不续写场景，不替玩家作决定；
- 可以坦率说明叙事意图、承认连续性问题、提出方案并接受玩家否定；
- 只输出给玩家看的自然纯文本对话，不输出 JSON、标签、内部说明或 Markdown 标题、列表、粗体、代码块等格式语法。

回到剧情的玩家输入要求模型：

- 把幕间全文视为非正史的创作讨论；
- 较晚的修改和否定覆盖较早的提议；
- 未经玩家同意的提议不得擅自采用；
- 直接输出正文，不提及幕间、讨论、约定或玩家要求。

## UI 方向

视觉采用“现代编辑室 / 拉开幕布”的克制方向：与 SillyTavern 主题融合的暖色中性表面、少量铜色强调、衬线标题与清晰正文层级。窗口使用原生 `dialog` 进入顶层，桌面为可展开的居中编辑室，移动端为安全区内的全高底部面板。

- 外壳优先于入场动效；入场使用 180–220ms 的透明度与轻微上移/缩放，不能让用户误以为点击没有生效。退场更快。
- 动效只使用 `transform` 和 `opacity`，并支持 `prefers-reduced-motion`。
- 对话按说话者形成阅读节奏，不使用重复的卡片气泡。
- 桌面端每条消息使用“左侧姓名栏 + 居中正文列 + 等宽右侧平衡栏”。玩家和叙述者共用同一条正文列；正文左对齐，但它的可见左、右留白必须对称，姓名不能把正文推向右侧。
- 移动端把姓名放到正文上方，正文使用同宽的左右 gutter，不为了保留侧栏而压窄内容。
- 玩家消息始终按纯文本转义显示。叙述者消息使用 SillyTavern 自带的 `messageFormatting` 与默认 DOMPurify 配置安全渲染 Markdown；接口不可用时回退为转义纯文本，绝不直接插入未经净化的模型 HTML。
- Markdown 仅作为模型偶尔不遵守纯文本要求时的显示兜底。段落、列表、引用、行内代码和代码块在幕间内使用克制的排版，不继承会破坏窗口宽度或层级的正文样式。
- 所有图标按钮有可读标签，键盘焦点可见，触控目标不小于 44px。
- 发送区支持 Enter 发送、Shift+Enter 换行和中文输入法合成保护。
- 加载、失败、停止和重试都有明确状态；失败不删除玩家刚才的话。
- 标题栏提供可发现的“清空本次幕间”文本操作；没有内容时禁用。清空不使用只有悬停才出现的隐藏图标。

## 验收

- 桌面和 390×844 移动视口均可打开、关闭、展开、输入、发送和继续。
- 点击“可以了，继续！”后，完整幕间讨论出现在下一次正文 provider 请求中，实际玩家输入显示为紧凑标记。
- 正常生成和流式生成都能关联会话版本。
- 修改幕间后生成新 swipe，旧候选的正文、事实和来源不会进入新候选。
- 幕间玩家楼不进入剧情摘要、近期原文正文、事实和时间证据；assistant 正文正常进入。
- 刷新、停止生成、切换已有 swipe 和切换分支后状态保持正确。
- `npm test` 全部通过，并在真实 UI harness 检查动画、焦点、移动端安全区和长文本滚动。
- 模拟 `saveMetadata()` 延迟 5 秒时，窗口仍在下一帧可见，发送后的玩家消息和等待状态也立即可见。
- 模拟会话恢复或 `getChatData()` 同步阻塞 1 秒时，窗口外壳仍必须先在下一帧完成绘制并显示 busy 状态；阻塞工作不能发生在首次绘制之前。
- 从点击处理函数到 `showModal()` 之间不得出现聊天数据读取；token 估算不得发生在输入解除禁用之前。
- 桌面端玩家与叙述者正文边界相同，正文列相对对话区水平居中；390×844 和 320×568 下姓名位于正文上方、左右 gutter 相等且没有水平溢出。
- 叙述者回复中的标题、粗体、列表、引用、行内代码和代码块由 SillyTavern Markdown 渲染并经过默认净化；玩家输入中的相同符号仍按字面显示。没有 `messageFormatting` 时安全回退为纯文本。
- 在保存延迟期间连续点击发送 10 次，最终只有 1 条玩家幕间消息和 1 次模型调用。
- 点击清空后当前讨论、草稿和未采用草稿立即消失；旧请求迟到返回时不会复活内容。
- 幕间模型请求只包含 system 指令、`l2`、`raw` 和幕间角色消息；测试中出现预设、角色卡、世界书、作者注释、`l1`、`l4` 或原生历史指纹即失败。
