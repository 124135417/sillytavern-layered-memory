# 非阻塞历史变更设计

## 目标

编辑消息、切换 swipe 和删除消息后，SillyTavern 的界面操作立即完成，不等待插件的元数据保存与记忆重算；但紧接着发生的重 roll 或其它生成必须先看到本次历史变更已经处理完，不能把旧候选或旧事实带进请求。

## 已确认故障

插件把 `MESSAGE_EDITED`、`MESSAGE_SWIPED` 和 `MESSAGE_DELETED` 事件直接绑定到一个被 `await` 的历史重算流程。SillyTavern 会等待事件监听器返回，因此一次本应很快的编辑保存被插件的聊天元数据保存与队列重建延长到约 2–3 秒。旧版 fire-and-forget 没有这个界面延迟，但会让立即重 roll 与后台清理发生竞态。

## 处理契约

1. 历史变更事件只登记工作，不把后台 Promise 返回给 SillyTavern；编辑保存、swipe 切换和删除的界面链路立即归还。
2. 每个聊天元数据对象拥有独立的历史变更协调器，切换聊天不会让旧聊天的工作获得新聊天的写入权限。
3. 同一聊天短时间连续发生多次变更时，正在处理的状态结束后只处理最新待处理状态；相同历史投影不重复重算。
4. 生成拦截器必须等待当前聊天的历史变更屏障。等待失败时中止生成并明确报错，不能以旧记忆继续请求。
5. 新 swipe 生成即使没有及时收到 UI 事件，也要主动登记“排除末条角色候选”的投影，然后等待同一个屏障。
6. swipe 生成与完成后的候选继续遵守既有指纹隔离；未选候选的原文、摘要和事实不得进入替代候选。
7. 历史重算与待提取楼层更新合并为一次必要的元数据持久化；投影未变化时不重复保存。

## 实现边界

- 新增一个不依赖 SillyTavern 的协调器模块，负责按聊天作用域串行、合并、去重并暴露等待屏障。
- `index.js` 负责从当前楼层投影生成稳定工作键，事件监听器只调度，生成拦截器负责等待。
- `src/queue.js` 接受“本轮必须持久化”的选项，由队列重建统一完成历史重算后的保存；普通无变化重建跳过重复保存。
- 不修改 SillyTavern 核心，不增加设置项，不改变用户操作方式。

## 错误处理

- 后台变更失败时记录日志并显示提示；下一次生成在屏障处收到同一错误并中止。
- 新的历史变更可以启动新一轮处理；旧错误不会永久锁死该聊天。
- 聊天切换仍由现有 `CHAT_SCOPE_CHANGED` 防护终止旧作用域写入。

## 验收

- 编辑、swipe 和删除监听器不返回长耗时异步任务。
- 连续登记相同投影只运行一次；运行中连续登记多个不同投影只追加最新状态。
- 在历史同步完成前发起生成，生成拦截器会等待；同步失败时生成被阻止。
- 新 swipe 在请求组装前完成共同前缀清理，旧候选仍不泄漏。
- 一次历史重算只做一次必要的元数据保存，普通无变化队列重建不保存。
- 完整测试套件通过。
