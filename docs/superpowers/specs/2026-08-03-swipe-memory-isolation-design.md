# Swipe 记忆隔离设计

## 目标

SillyTavern 的多个 swipe 是同一角色楼的互斥候选。插件只能继承该角色楼之前的共同聊天前缀；未选中的候选回复、由它生成的逐楼摘要、章节摘要、当前事实、检索索引和近期完整原文都不得进入另一条 swipe 的生成请求。

## 已确认故障

生成一个全新 swipe 时，SillyTavern 会先把最后一条角色消息的 `swipe_id` 指向尚不存在的新槽位，同时暂时保留旧 `mes`。插件此前把这个旧 `mes` 当作当前正文，重新注入“近期完整剧情原文”。`GENERATION_STARTED` 已提供 `type === "swipe"`，但插件没有使用它。swipe 事件处理器也没有把异步清理返回给 SillyTavern，旧事实清理可能与下一次生成竞态。

## 隔离契约

1. 新 swipe 的空槽位不是一条有效角色消息，不得视为已定格楼层。
2. 组装 swipe 请求时，插件以“移除末条角色消息后的聊天”为投影；投影末尾的用户消息由 SillyTavern 原始 Chat History 承载，不在插件近期原文中重复。
3. 切换到已有 swipe 时，当前正文指纹改变，插件必须在事件完成前按新指纹重算记忆。
4. 生成新 swipe 前，插件必须按共同前缀重算当前事实、逐轮记录、章节和检索索引，然后才允许 Prompt Manager 展开宏或兼容注入。
5. 新候选生成完成后，再按其新指纹建立该候选自己的记忆；旧候选内容不得复用。
6. 清理时替换当前聊天的记忆数据对象，使仍在运行的旧候选后台任务触发既有 `CHAT_SCOPE_CHANGED` 保护，不能把旧结果写回。
7. 普通生成、继续生成、角色代替用户发言、Fork 恢复和非 swipe 后台任务保持原行为。

## 实现边界

- `src/ids.js` 识别待生成 swipe 空槽，并提供排除末条角色消息的消息楼层和对话对投影。
- `src/inject.js` 保存当前生成类型；预设宏和兼容注入都按 swipe 投影渲染。
- `index.js` 等待 swipe 清理完成，使用 `GENERATION_STARTED` 的类型，并在 swipe 回复落盘后重算当前历史。
- `src/branch.js` 在处理当前活动聊天时以新对象替换旧记忆状态，隔离已在运行的旧任务。
- `src/queue.js` 与 `src/narrative.js` 在 swipe 投影下只补共同前缀，不为被替换的角色楼排队。

## 验收

- 已存在候选之间左右切换后，注入只含当前候选。
- 向右生成新候选时，即使 `mes` 暂时仍是旧候选，核心记忆、近期原文和预设宏都不含旧候选。
- 旧候选产生的当前事实从新 swipe 请求中消失。
- 清理前启动的旧后台任务不能在清理后保存结果。
- 新候选完成后可以按自己的正文重新整理。
- 完整测试套件通过，并新增覆盖“`swipe_id === swipes.length` 的空槽”而非只覆盖已有候选切换。

## 非目标

- 不改变 SillyTavern 保存 swipe 候选的格式。
- 不让不同 swipe 复制共同前缀之前的整套聊天文件。
- 不增加用户设置；swipe 隔离是正确性约束，不能由用户关闭。
