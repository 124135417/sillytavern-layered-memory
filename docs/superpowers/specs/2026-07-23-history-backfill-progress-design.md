# 旧聊天补记进度与停止设计

## 目标

“补记以前的聊天”必须像一个可理解、可恢复的后台任务：点击后立即确认已经开始，持续显示完成轮数、总轮数和当前阶段；刷新或重新打开面板后仍能看到真实状态；停止时取消尚未执行的任务，并明确说明正在执行的单个请求会安全收尾。

## 状态与进度

每个聊天在插件元数据中保存 `history_backfill`：状态、总轮数、开始/完成/停止时间和最后错误。完成轮数不依赖临时计数器，而是根据该聊天基线以前已经存在的 `migrated:<floorKey>` 或普通提取键实时计算，因此刷新、重试和恢复队列后不会虚报。

状态为 `idle | running | stopping | stopped | complete | error`。补记队列增加最后一个 `migrate_complete` 任务；只有它执行后才标记完成并创建分支检查点，避免当前实现过早宣称收尾完成。

## 界面

设置页的补记区域常驻显示：

- `已整理 x / y 轮`、百分比进度条；
- 当前阶段，例如“正在整理第 26–50 轮剧情”“正在提取重要事实”“正在处理剩余对话”；
- 等待任务数量，以及失败时的自然语言错误；
- 运行时禁用重复开始；停止后按钮改为“继续补记”。

点击开始后立即更新区域并显示轻提示。点击停止后先显示“正在停止”；未开始的补记任务立即从持久队列移除，正在进行的模型请求允许结束，随后显示“已停止在 x / y”。重新开始只安排尚未完成的范围。

## 无父记忆的旧分支

旧 Fork 的父聊天从未使用本插件时，不属于恢复故障。插件创建空的当前分支状态，从当前聊天末尾开始记录，并提示用户可按需手动补记旧聊天；不自动触发大量模型请求，也不显示“分支记忆恢复失败”。

## 验收

- 开始、进行中、完成、停止中、已停止和失败均有可见反馈。
- 刷新设置页或页面后进度保持一致。
- 重复点击开始不产生重复任务；继续补记不重复已完成范围。
- 停止会清除尚未执行的所有 `migrate_*` 任务。
- 最后一项完成前不得显示 100%。
- 父聊天无插件数据的旧 Fork 正常启动，不注入父分支内容，也不自动补记。
