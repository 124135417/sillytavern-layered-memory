# 预设无关的 Chat History 交接设计

## 目标

启用分层长程记忆后，用户更换 Chat Completion 预设时只需要把
`{{layered_memory_context}}` 放到希望注入记忆的位置，不再为每个预设编写删除旧
Chat History 的正则。

本次只解决主模型请求里的旧聊天重复问题，不改变“AI 正文提取规则”。

## 已确认的 SillyTavern 1.13.5 边界

普通生成会先复制并处理聊天消息，再调用扩展 `generate_interceptor`，之后才扫描世界书并由
Prompt Manager 组装最终请求。SillyTavern 暴露的 `context.symbols.ignore` 可以标记一条请求消息：
消息继续留在预处理数组中，但 Chat Completion 转换时不发送给模型。

因此不能删除或清空旧消息。插件应保留其正文、数组位置和元数据供世界书、楼层深度及其它
酒馆逻辑读取，只在本次请求的克隆对象上增加结构化忽略标记。

## 交接规则

1. 插件关闭、`setExtensionPrompt` 不可用或 `symbols.ignore` 不可用时，不隐藏任何消息。
2. 每条真实聊天消息必须通过 `extra.layered_memory_id` 映射到插件当前分支的可见楼层；映射不完整时整次交接安全跳过。
3. 普通生成且请求末条为用户消息时，保留该用户消息；此前所有已由插件记忆覆盖的楼层标记为忽略。
4. 请求末条为角色消息时，保留该角色消息及紧邻的用户消息作为活动尾部。这覆盖 continue、impersonate、工具递归和无新用户消息的自动生成。
5. swipe 使用 SillyTavern 已移除旧候选后的请求副本；插件记忆也排除旧候选，并保留共同前缀末尾的用户消息。
6. 被忽略消息只克隆顶层对象和 `extra` 后写入 Symbol；不得修改 `SillyTavern.getContext().chat`、正文、附件或聊天存档。
7. 插件注入的近期原文和逐楼摘要使用与活动尾部相同的排除边界，避免同一楼层同时出现在插件记忆和原生 Chat History。
8. 预设缺少锚点时继续使用现有系统提示兼容注入；锚点缺失不能导致“隐藏历史但没有记忆”。
9. 非 Chat Completion 或无法证明支持结构化忽略的运行时安全跳过，不尝试用正则、文本哨兵或数组删除兜底。

## 生成模式

| 请求末尾 | 原生保留 | 插件接管 |
|---|---|---|
| 用户消息 | 当前用户消息 | 更早全部可见楼层 |
| 角色消息 | 最近用户消息 + 当前角色消息 | 更早全部可见楼层 |
| swipe 待生成候选 | 共同前缀末尾用户消息 | 更早全部可见楼层；旧候选完全排除 |

活动尾部内的图片、文件、工具调用、姓名和角色由 SillyTavern 原生路径继续处理。更早楼层的正文由插件的近期完整原文、逐楼/章节/长期摘要和当前事实接管。

## 失败策略

- 消息 ID 缺失、分支映射不一致或记忆注入 API 不可用：保留完整原生历史并记录一次诊断。
- 未知生成模式：按请求末条角色推导活动尾部，不按预设文字或标签猜测。
- 拦截器异常：不调用 `abort`，保持 SillyTavern 原请求不变。
- dry run：SillyTavern 1.13.5 不调用生成拦截器；不得把 dry-run Prompt Manager 预览冒充真实交接证据。

## 验收

- 普通生成的旧楼层带结构化忽略标记，当前用户消息不带标记。
- continue/impersonate/工具式尾部保留最近用户与角色消息。
- swipe 不把旧候选放入插件记忆或原生活动尾部。
- 世界书仍能读取被忽略消息的原文，消息数组长度和顺序不变。
- 原始聊天对象及其 `extra` 没有 Symbol 或其它修改。
- 映射失败、插件关闭和能力缺失均 fail closed。
- 现有正文提取、分支恢复、队列、UI 和移动端测试全部通过。
- 真实非 dry-run 最终请求中，被插件接管的旧消息不存在；当前输入、锚点记忆和必要活动尾部存在且顺序正确。
