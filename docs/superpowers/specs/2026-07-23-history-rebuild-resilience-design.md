# 旧聊天安全重建容错设计

## 目标

修复模型已经返回可用内容、却因少量格式偏差导致整段和整个重建失败的问题。本次只处理输出归一化、事实降级、单轮失败隔离和续跑；批量输入的因果隔离另行设计。

## 输出归一化

- 逐轮摘要仍必须记录用户本轮的行为或话语。
- 摘要以 `<user>`、当前用户名、`用户` 或 `你` 开头时，统一保存为 `<user>`。
- 摘要确实遗漏用户行为时才视为该轮失败，错误文案不得再把“包含”误写成“开头”。
- evidence 先移除包裹引号，再尝试原文精确匹配；精确匹配失败时，允许空白及中英文常见标点差异，并恢复成原文中的连续片段。
- 匹配成功但超过 50 字时，保存对应原文的前 50 字；无法恢复到原文时丢弃该事实。

## 部分成功与重试

- 分段返回后按轮独立校验，合格轮次立即写入暂存区。
- 无效事实只从该轮 facts 中剔除并记录警告，不使正确的逐轮摘要失败。
- 第一遍只把失败轮次交给第二次请求；重试 Prompt 包含具体错误和对应原文，不再重复请求整个分段。
- 第二次仍失败的轮次写入 `unresolved_floors`，其他分段继续处理。
- 依赖缺失轮次的章节暂不生成；所有轮次和章节完整之前不得执行最终原子替换。
- 重建最终进入“需要处理”状态，而不是把暂存进度丢弃。点击继续时只入队缺失轮次、缺失章节和最终提交。

## 状态与界面

- 进度以已写入暂存区的逐轮记录为准。
- 错误区显示具体失败轮数，不再只显示整段范围。
- 已丢弃的可疑事实计入重建警告，但不算失败轮次。
- 继续重建复用现有暂存结果，不重新调用已经成功的轮次。

## 验收

- 当前用户名、`用户`、`你` 开头的摘要可被归一化并通过。
- evidence 的包裹引号、换行和常见标点差异可恢复为原文连续片段；超过 50 字会安全截短。
- 无法匹配的 evidence 只丢弃对应事实。
- 13 轮中一轮摘要不合格时，12 轮仍保存，第二次只请求失败轮次。
- 单轮连续失败不会取消其余分段；最终提交保持关闭。
- 刷新或点击继续后只补缺失轮次。
- 旧结果在完整重建通过前始终保留。
