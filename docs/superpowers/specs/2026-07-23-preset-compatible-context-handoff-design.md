# 预设兼容的上下文交接设计

> 日期：2026-07-23  
> 状态：用户已确认，进入实现  
> 目标：保留插件主动减少上下文的价值，同时不破坏不同预设各自的提示词正则与摘要格式。

## 1. 已确认的真实执行顺序

SillyTavern 在普通生成中先复制聊天消息并执行 `promptOnly` 正则，再把处理后的 `coreChat` 交给第三方扩展的 `generate_interceptor`。插件只能修改本次请求使用的副本，不删除聊天存档。拦截器结束后，SillyTavern 继续加入角色卡、预设、世界书和扩展提示词，并由自己的 Prompt Manager 执行最终总上下文预算。

当前线上预设 `MoM☫蛾摩拉2.33修复` 是兼容验收样本：

- 第 5 楼以外的 AI 回复只保留 `<meow_FM>`；
- 第 3 楼以外从 `<meow_FM>` 中移除 `seeds`；
- 其它规则还会移除段评、作者说明、小剧场和日程表等内容；
- 插件必须基于这些规则处理后的文本计算聊天历史用量，不能回到原始正文重新决定请求中的大小。

## 2. 职责边界

| 组件 | 唯一职责 |
|---|---|
| 用户预设与正则 | 决定每一楼发送给模型时保留什么格式和内容 |
| 插件章节/卷 | 覆盖将从请求中删除的更早剧情 |
| 插件长期事实 | 提供至今仍然成立的状态、关系、承诺和设定 |
| 插件裁剪器 | 在正则执行后，按聊天历史预算删除最旧且已有摘要覆盖的连续前缀 |
| SillyTavern Prompt Manager | 计算角色卡、预设、世界书、插件注入和聊天的最终总上下文 |

插件不解析或改写 `<meow_FM>`、`<dog>`、馆藏等预设私有格式，也不修改用户的正则配置。

## 3. 安全裁剪算法

普通生成时，插件执行以下步骤：

1. 用 `extra.layered_memory_id` 将正则处理后的克隆消息映射回原始对话轮次；禁止依赖对象引用相等。
2. 估算正则处理后聊天副本的 token 数。
3. 根据模式计算聊天历史预算：节省 25%、平衡 40%、尽量完整 60%，百分比以拦截器收到的模型总上下文为基准；高级设置可以直接指定 token。
4. 至少保留用户设置的最近完整轮次，默认 6 轮。
5. 仅删除从最旧轮次开始、连续且被非 stale 章节或有效卷完整覆盖的前缀。
6. 一旦遇到未覆盖、stale、消息 ID 缺失或无法配对的轮次，停止扩大删除范围。
7. 若达到安全边界后仍超过聊天预算，保留剩余内容并交给 SillyTavern 最终预算器处理，绝不跨越未覆盖历史继续删除。
8. 重新生成、继续生成、角色代替用户发言及未知生成类型不裁剪。

裁剪只影响当前请求；不得调用删除聊天、保存裁剪副本或改写原始 `mes` 的接口。

## 4. 摘要注入范围

L1 长期事实继续按现有预算注入。L2 改为只渲染“本轮实际删除前缀”所需的章节或卷：

- 仍留在聊天请求中的轮次不得重复注入对应章节摘要；
- 卷有效时优先使用卷，且不得同时注入其已覆盖的降级章节；
- 卷缺失、stale 或覆盖不完整时使用非 stale 章节；
- 没有发生安全裁剪时，L2 为空；
- L4 保持显式开关，默认关闭。

由于 extension prompt 在拦截器之后才进入最终组装，裁剪器必须先计算并记录本轮截止轮次，再调用 `updateInjection` 按该截止范围更新 L2。

## 5. 设置与诊断

常用设置增加“希望保留多少最近剧情”：

- 节省上下文：聊天历史最多使用总容量的 25%；
- 平衡：40%，默认；
- 尽量完整：60%；
- 自定义：使用高级设置中的聊天历史 token 上限。

“至少保留最近完整对话”默认 6 轮。旧字段 `recentPairs` 软迁移为该值，不能让已有用户突然回到更小的默认值。

每次拦截记录只读诊断：生成类型、模型总上下文、正则处理后聊天 token、目标预算、删除轮次范围、保留轮次范围、未覆盖阻断点、L1/L2/L4 token。诊断不得包含聊天正文、摘要正文、API Key 或供应商响应。

记忆中心的发送预览使用最近一次真实裁剪结果；尚未生成时明确标记为“预计”，不能把估算冒充实际请求。

后台提取和章节整理仍读取存档原文，以免提示词正则永久丢掉细节；但辅助模型必须把预设附加的回顾摘要、状态表、思考过程、写作计划和界面组件视为参考元数据，而不是本轮新剧情或可独立引用的事实证据。该规则按语义判断，不绑定任何作者私有标签名。

## 6. 失败策略

- ID 映射失败：不裁剪，记录安全跳过原因。
- 章节或卷 stale：停止在该范围之前继续裁剪。
- 摘要范围有空洞：停止裁剪。
- token 估算异常：不裁剪。
- 插件异常：不阻止主生成。
- 设置从旧版本迁移失败：采用“平衡 + 至少保留 6 轮”，但不覆盖用户已明确设置的更大保留轮数。

## 7. 验收测试

自动化测试必须覆盖：

1. SillyTavern 风格的克隆消息对象仍可按稳定 ID 映射；
2. `<meow_FM>` 等正则压缩后的短文本用于 token 预算；
3. 被摘要覆盖的连续旧前缀可以删除；
4. 激活基线以前未迁移的历史不得删除；
5. stale、空洞、缺 ID 或未配对历史触发 fail-closed；
6. 最近最少保留轮数始终生效；
7. 只注入实际删除范围对应的摘要；
8. regenerate/continue/未知类型不裁剪；
9. 裁剪不修改 `SillyTavern.getContext().chat`；
10. UI 文案不暴露 L1/L2/L4 等内部术语，并在移动端保持可操作。

此外需要用当前线上预设的正则结构做一次请求级验收：确认正则先压缩、插件后裁剪、最终请求不存在同一楼层“正则摘要 + 插件章节摘要”的重复覆盖。
