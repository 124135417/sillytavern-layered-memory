# 逐轮剧情记录透明度设计

## 目标

让用户能够核查安全重建生成的每一轮小摘要，同时保持时间线默认简洁，并明确说明这些记录如何在 Fork 到章节中间时接替跨界章节。

## 界面

- 每张完整章节卡片增加“逐轮记录 N 条”折叠区，按轮数显示该章范围内的逐轮摘要。
- 不属于任何完整章节的末尾记录单独显示为“尚未合并的剧情记录”，默认折叠并标明数量与轮数范围。
- 每条记录只显示自然语言轮数和摘要，不展示 `floorKey`、指纹或内部 ID。
- 重建进度明确显示“已生成 N / M 条逐轮记录”；完成后仍显示总数。
- 桌面和手机均默认折叠，展开列表在卡片内部纵向排列，不横向滚动。

## 数据与行为

- UI 只读取现有 `turn_summaries`；不新增模型调用、不复制数据，也不改变注入和 Fork 行为。
- 章节内记录按 `pairIndex` 升序匹配章节 `floor_range`。
- 尾部区域只包含未被任何章节完整覆盖的逐轮记录，避免同一条记录展示两次。
- 重建进行中，进度数量读取暂存区 `history_rebuild.turn_summaries`；重建完成后读取正式 `data.turn_summaries`。
- 数据缺失时显示实际可用数量，不伪造 25 条或用章节摘要反推逐轮内容。

## 验收

- 124 条逐轮记录能够被统计，其中完整章节各自显示对应记录，未成章部分单独显示。
- 章节展开后轮数有序、无重复、无内部 ID。
- 进度卡在运行和完成状态都显示逐轮记录数量。
- 320×568、390×844 和桌面尺寸无横向溢出，展开与收起可操作。
