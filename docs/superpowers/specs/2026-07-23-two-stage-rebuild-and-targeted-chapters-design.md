# 两阶段重建与单章定向更新设计

## 目标

旧聊天安全重建分成两个由用户明确控制的阶段。逐轮记录先完整生成、展示并允许编辑；只有用户确认后才调用模型生成章节摘要。修改某条逐轮记录时，只让覆盖该轮的章节失效，并由用户按需重新生成该章。

## 阶段一：逐轮记录草稿

- “安全重建旧结果”只入队缺失的逐轮记录任务。
- 所有逐轮记录完成后，状态变为 `review`，不生成章节、不替换正式记忆，也不继续产生 API 调用。
- “剧情时间线”显示独立的“重建草稿”区域，按设定的章节大小分组；未满一章的尾部同样可见。
- 每条草稿提供“编辑”操作。用户保存后写入 `manual_override=true`，后续恢复、重试和刷新不得覆盖。
- 草稿编辑只改变剧情记录，不暗中改变结构化事实；界面明确说明这一边界。

## 阶段二：章节与提交

- 设置页在 `review` 状态显示“根据逐轮记录生成章节摘要”。
- 用户点击后才入队缺失章节及最终提交任务。
- 章节生成必须读取当前草稿，包括人工修改后的内容。
- 全部完整章节通过后，沿用原子替换；不足一章的尾部逐轮记录直接保留。
- 从旧版本升级时，尚在运行且没有阶段标识的重建按“逐轮阶段”处理；旧队列中的章节和提交任务不得越过审核阶段。

## 完成后的逐轮编辑

- 正式时间线中的每条逐轮记录也提供“编辑”。
- 保存后同步更新对应 Fork 事件中的 `turnSummary`，并把覆盖该轮的章节标记为“逐轮记录已修改”。
- 章节卡显示“根据修改后的记录重新生成本章”。点击后只入队该章的范围；不重新生成其他章节，也不重新提取逐轮记录。
- 单章生成成功后原地保留章节 ID，更新摘要、关键事件、coverage 和关键词，清除失效及人工章节覆盖标记。
- 若该章属于长期摘要，则对应长期摘要标记为需要更新，但不自动产生额外模型调用。

## 状态与恢复

- `history_rebuild.stage_mode` 为 `turns` 或 `chapters`。
- `review` 状态和人工草稿保存在聊天元数据中，刷新、切聊和重启后继续存在。
- “继续安全重建”根据 `stage_mode` 只恢复当前阶段。
- 停止逐轮阶段后只补缺失轮次；停止章节阶段后只补缺失章节。

## 验收

- 第一阶段结束时章节调用数为零，状态停在审核。
- 修改第 24 轮后，阶段二生成的第 0–24 轮章节使用修改文本。
- 正式结果中修改第 24 轮，只使第 0–24 轮章节失效。
- 点击单章更新只产生一个章节请求，其他章节内容和 ID 不变。
- 人工修改的逐轮记录在刷新、继续重建和失败重试后仍保留。
- 重建完整提交前，当前模型注入继续使用旧的合格正式结果。
- 桌面、390×844 和 320×568 均可查看、编辑逐轮记录并触发单章更新。
