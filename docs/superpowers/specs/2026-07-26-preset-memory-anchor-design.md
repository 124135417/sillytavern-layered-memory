# 预设协作式记忆锚点设计

## 目标

让预设决定记忆在最终提示词中的准确位置，插件只提供记忆内容，不再依赖 Prompt Manager 的相对注入顺序猜测 `<前文回顾>` 所在位置。

当前预设可在前文回顾开头、Chat History 之前放置：

```text
{{layered_memory_context}}
```

SillyTavern 在组装该条预设提示时原地展开宏。展开内容继承宿主提示的顺序与角色，不创建独立的 system、user 或 assistant 消息，也不参与 `IN_CHAT` 的 depth/order 排序。

## 锚点契约

- 宏名固定为 `layered_memory_context`，预设中使用完整标记 `{{layered_memory_context}}`。
- 插件只按完整标记计数，不通过正则猜测 `<前文回顾>`、提示词名称或自然语言内容。
- 只有当前启用的预设提示中的锚点才算有效。禁用提示里的标记不应关闭兼容注入。
- 恰好一个有效锚点时进入锚点模式。
- 没有有效锚点时使用现有 `IN_PROMPT` 核心记忆注入，保证普通预设继续工作。
- 多于一个有效锚点时，宏展开为空并使用一次兼容注入，避免重复向模型发送核心记忆。
- SillyTavern 未提供宏注册接口时使用兼容注入并显示不支持状态。

## 记忆内容与顺序

锚点展开内容由现有 L2 与 L1 组成：

1. L2 已发生剧情按真实聊天楼层从早到晚排列。
2. L1 当前仍然成立的事实放在剧情之后、Chat History 之前，作为续写时的当前承接状态。

插件不生成 `<前文回顾>` 标签，不重复预设的“牢记前文”承诺，也不修改预设中的写作、角色或 CoT 规则。原有 L2 分段边界与真实楼层标注继续保留。

L4 仍按设置作为可选的 `IN_CHAT` 检索记忆发送，不进入本次锚点协议。

## 运行流程

1. 插件加载时注册宏，宏值由函数按当前聊天实时渲染。
2. 每次更新注入前检查当前 Chat Completion 预设的 `prompts` 与启用顺序。
3. 单锚点模式下清空旧的 L1/L2 extension prompt；宏返回完整 L2+L1 内容。
4. 缺失、重复或不支持宏时，宏返回空字符串；L1/L2 继续通过兼容 `IN_PROMPT` 注入。
5. 切换预设后重新检查并刷新注入与界面状态，不持久化旧预设的检测结果。
6. 插件关闭时宏返回空字符串，并清空所有 extension prompt。

## 可见状态

“当前记忆”页底部显示：

- `预设锚点 已连接：提示词名称`；
- `预设锚点 未添加，正在使用兼容注入`；
- `预设锚点 重复 N 处，正在使用兼容注入`；
- `当前 SillyTavern 不支持预设锚点，正在使用兼容注入`。

预览同时显示 L2 剧情摘要和 L1 当前事实，不再错误声称剧情摘要没有发送。

## 验收

- 单个启用锚点：宏返回完整 L2+L1，`layered_memory_l1` 和 `layered_memory_l2` 均为空。
- 没有锚点：宏返回空，L1/L2 保持 `IN_PROMPT + SYSTEM` 兼容注入。
- 锚点所在提示被禁用：按没有锚点处理。
- 两个启用锚点：两个宏均展开为空，L1/L2 只通过兼容路径发送一次。
- L2 在锚点内容中位于 L1 之前；L4 行为不变。
- 切换预设事件会刷新检测结果。
- UI 准确显示当前模式、锚点数量、宿主提示名称和实际预览内容。
- 最终在 SillyTavern 的 Prompt Manager“查看输入”中确认核心记忆只出现一次，并位于预设的 `<前文回顾>` 开头与 Chat History 之间。
