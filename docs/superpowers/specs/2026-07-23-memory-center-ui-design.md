# 分层长程记忆中心 UI/UX 定稿设计

> 日期：2026-07-23
> 状态：用户已确认视觉方向与承载方式，待书面规格复核
> 关联设计：[`2026-07-21-layered-memory-design.md`](./2026-07-21-layered-memory-design.md)
> 参考方向：对比稿 C「记忆主视图 + 常驻任务轨」

## 1. 已确认决策

| 主题 | 决策 |
|---|---|
| 产品形态 | 纯 SillyTavern 第三方 UI Extension，不依赖酒馆助手 |
| 主入口 | SillyTavern 顶部菜单中的独立记忆按钮，打开大尺寸 drawer |
| 次入口 | Extensions 菜单内提供「分层长程记忆」快捷入口 |
| 扩展设置栏 | 只保留启用、健康摘要和「打开记忆中心」；不承载完整产品界面 |
| 首页方向 | C：记忆内容是主体，后台任务以常驻任务轨呈现 |
| 副模型设置 | 放在「设置 → 副模型连接」；首页只显示连接健康状态，不显示 URL/Key |
| 刷新策略 | 禁止任务完成后硬刷新页面；所有区域按状态增量重绘 |
| 界面语言 | 中文 |

设计目标不是仿制其他插件的内部实现，而是采用成熟的顶部 drawer 承载方式，同时保留本插件按聊隔离、分层注入和可恢复任务的边界。

## 2. UX 目标

用户打开记忆中心后，应在五秒内回答四个问题：

1. 系统有没有正常工作？
2. 记忆已经处理到哪一楼？
3. 当前真正记住了什么？
4. 如果失败，我能否重试、暂停或查明原因？

界面优先建立长档安全感，不展示无法解释的“运行中”动画，也不把失败埋进控制台。所有状态必须来自真实数据；没有数据时显示空状态，不使用演示数字。

## 3. 信息架构

### 3.1 顶部状态栏

固定在 drawer 顶部，包含：

- 产品名「分层长程记忆」与当前聊天名称
- 总体状态：`正常`、`处理中`、`需要处理`、`已暂停`
- 已同步至第 N 对、最后成功时间
- 当前事实数、待审数
- 副模型连接健康灯
- 关闭 drawer 按钮

总体状态按严重度归并：失败任务 > 暂停 > 运行中/排队 > 正常。只显示一个主状态，详细原因放在任务轨中。

### 3.2 主导航

四个一级页签：

1. **当前记忆**：默认首页
2. **剧情时间线**：章节、卷摘要与 stale 状态
3. **待审**：冲突、校对建议、压缩确认
4. **设置**：连接、预算、自动化、迁移和诊断

待审页签显示数量徽标；数量为 0 时不显示徽标。

### 3.3 当前记忆页

桌面端使用“主内容 + 任务轨”双栏：

```text
┌──────────────────── 顶部状态栏 ────────────────────┐
│ 当前记忆  剧情时间线  待审  设置                    │
├───────────────────────────────┬─────────────────────┤
│ 搜索 / 筛选 / 添加             │ 后台任务            │
│                               │ 运行中               │
│ 身体状态                       │ 排队                 │
│  └ 记忆卡片                    │ 失败与重试           │
│ 承诺与关系                     │ 注入预算             │
│  └ 记忆卡片                    │                     │
├───────────────────────────────┴─────────────────────┤
│ 本次生成将注入……                  预览模型所见       │
└─────────────────────────────────────────────────────┘
```

主列约占 70%，任务轨约占 30%，任务轨宽度限制在 240–320px。主列内容按 slot 分组；空分组不出现。

### 3.4 记忆卡片

每张卡片包含：

- 主体/关系标题
- 当前事实正文
- 来源楼或迁移章节
- 原文证据入口
- `持续影响`、`钉住`、`冲突` 等必要标记
- 次级操作：编辑、钉住、查看变更历史、删除

默认只显示最常用信息；操作在 hover、键盘聚焦或卡片菜单中出现，避免每张卡片堆满按钮。删除必须二次确认；普通编辑保存后原位更新，不跳页。

搜索同时匹配主体、对象、事实、证据和来源。筛选至少支持 slot、钉住、待审、最近更新。搜索结果中高亮匹配文本，但不得改写原内容。

### 3.5 常驻任务轨

任务分四组显示：

- **正在运行**：任务名、楼/章、已用时间、当前尝试次数
- **等待中**：队列顺序与原因
- **失败**：简短错误、重试次数、立即重试、展开详情
- **最近完成**：最近 3–5 条结果摘要

允许“暂停新任务”，但不粗暴中止已经发出的模型请求。失败任务不得因切页、关闭 drawer 或刷新浏览器而从状态中消失。

同一时刻只允许一个明确的主操作。重试后按钮进入 disabled/loading 状态，禁止重复点击制造重复任务。

### 3.6 底部注入摘要

显示下一次普通生成预计注入的真实内容规模：

- L1 事实数量与预算占用
- L2 章节/卷数量与预算占用
- L4 命中数量（关闭或零命中时明确显示）
- L3 保留的近楼范围

「预览模型所见」打开只读弹窗，按最终拼装顺序显示经过预算与裁剪后的文本。它是诊断工具，不提供直接编辑，避免“改预览”和“改源数据”产生双写。

## 4. 其他页面

### 4.1 剧情时间线

按时间倒序展示章节；每章显示楼层范围、摘要、关键词、冻结/钉住/stale/已入卷状态。stale 章必须解释原因，并显示“等待重建”“重建中”或“重建失败”，不能只给一个红点。

章节正文默认折叠。编辑摘要会明确提示“保存后作为人工版本冻结”；源消息后续被改动时仍标 stale，不用“冻结”掩盖过期内容。

### 4.2 待审

按风险排序：冲突 > 压缩确认 > 校对建议。每项并排展示当前值、建议值、来源证据和影响范围。操作为批准、驳回、编辑后批准；批准后从列表原位移除，并提供短时可撤销提示。

空状态文案为“没有需要你确认的内容”，同时显示最近一次校对时间，而非空白页。

### 4.3 设置

设置按任务而非按内部模块分组：

1. **副模型连接**
   - Connection Profile（优先）
   - 启用 Fallback
   - Base URL
   - API Key（密码框，默认不回显明文）
   - 模型名
   - 测试连接
   - 测试结果、耗时与可理解错误
2. **记忆与注入**
   - L1/L2/L4 预算、近 N 对、depth
3. **自动整理**
   - 章大小、校对周期、卷压缩确认、L4 开关
4. **存量迁移**
   - 迁移范围、开始/暂停、进度、错误恢复
5. **诊断与错例**
   - 导出、重跑、诊断日志

Fallback 明确注明仅支持 OpenAI 兼容 `/chat/completions`，浏览器直连可能遇 CORS，Key 保存于 SillyTavern `settings.json`。连接测试不得把 Key 或完整供应商响应写入界面日志。

设置有未保存修改时，关闭 drawer 或切换聊天前提示；保存成功原位反馈，不刷新页面。

## 5. 响应式与主题

- ≥ 900px：主内容 + 常驻任务轨双栏
- 600–899px：任务轨收为可展开的底部状态条；失败时自动露出一行摘要
- < 600px：单栏，顶部指标横向滚动或压缩为两行；卡片操作进入更多菜单
- drawer 高度以当前视口为准，内部滚动；禁止页面和 drawer 同时出现难以控制的双滚动
- 使用 SillyTavern 主题变量作为背景、文字、边框和强调色来源
- 成功/警告/失败不能只依赖颜色，同时配图标和文案
- 尊重 `prefers-reduced-motion`；普通过渡 120–180ms，不使用长动画

视觉还原目标：桌面版保持对比稿 C 的布局、密度、暗色层级、卡片和任务轨，预计达到 90–95%；固定像素宽高必须让位于 SillyTavern drawer、主题和移动端适配。

## 6. 状态、数据流与安全边界

### 6.1 UI shell

新增薄 `ui-shell` 负责：

- 插入顶部 drawer 与 Extensions 菜单入口
- 暴露唯一 `openMemoryCenter(targetTab?)`
- 管理打开/关闭、响应式与兼容 fallback
- 监听聊天切换并更新当前 view model

业务模块不得依赖 drawer DOM。SillyTavern 选择器和内部行为只允许出现在兼容层，便于酒馆升级后单点修复。

### 6.2 渲染模型

UI 从只读 view model 渲染，不直接拼接和修改底层 metadata。用户操作调用明确 command，再由业务层保存并发布状态变更。任务完成只更新受影响区域；禁止 `location.reload()` 或等价硬刷新。

### 6.3 上线前可靠性前置条件

以下不是视觉增强，而是 C 方案能如实工作的前置条件：

1. 队列和 in-flight 结果按 chat identity 隔离；切聊后旧结果不得写进新聊天
2. pending、失败、重试次数和任务身份可在刷新后恢复
3. 消息稳定 UUID 写入后明确持久化
4. `regenerate`、`continue`、`impersonate`、`swipe` 的裁剪行为与文档统一
5. UI 重绘、打开 drawer 和连接测试不得触发无限入队

如果底层尚不能提供真实状态，UI 必须显示“不可用/尚未持久化”，不得伪装成“运行正常”。

## 7. 错误与空状态文案

| 场景 | 界面行为 |
|---|---|
| 新聊天，无记忆 | 解释将在下一楼定格后开始提取；提供手动添加，不制造警告 |
| 未配置副模型 | 顶部显示“未连接”，任务不反复自动重试；按钮直达连接设置 |
| 网络暂时失败 | 有上限的退避重试，展示下一次尝试；耗尽后停在失败状态 |
| 切换聊天 | 立即切换 view model；旧聊天任务继续受隔离管理，不污染当前页 |
| 浏览器刷新 | 从持久化状态恢复任务列表；不得把未知任务显示为成功 |
| 数据过多 | 分组渐进渲染或分页；搜索、编辑不因全量重绘丢失焦点 |
| 连接测试失败 | 区分鉴权、模型不存在、CORS、超时和格式不兼容 |

错误详情默认折叠，并提供复制诊断信息；复制内容必须清除 API Key、Authorization 和完整供应商响应。

## 8. 可访问性与交互质量

- drawer 打开后焦点进入标题；关闭后回到顶部记忆按钮
- 所有图标按钮有可见 tooltip 与 `aria-label`
- 页签、卡片菜单、弹窗、确认操作可用键盘完成
- loading 不移除按钮宽度，避免布局跳动
- toast 只用于短暂确认；需要用户处理的失败必须留在页面中
- 保存、重试、批准等动作防重复提交
- 长文本折叠时保留“展开全文”，不得用 CSS 截断后永久不可见

## 9. 验收

### 9.1 视觉/交互

- 在桌面 viewport 中与 C 对比稿逐区核对布局、密度、层级和文案
- 900px、600px 两个断点无横向溢出或双滚动
- SillyTavern 至少两个明暗主题下文字和状态可辨
- 键盘可完成打开、切页、编辑、保存、重试和关闭

### 9.2 状态与故障

- 空聊天、正常、排队、运行、失败、暂停、stale、待审均有可辨状态
- 任务完成不整页刷新，输入焦点和滚动位置保持
- 快速重复点击不会产生重复任务
- 切聊期间完成的旧任务只写回旧聊天
- 刷新后队列和失败任务恢复一致
- 无配置、错误 Key、错误模型、CORS、超时分别给出可理解反馈
- 敏感信息不进入诊断日志、toast、复制内容或测试快照

## 10. 非目标

- 不在本轮引入酒馆助手依赖
- 不照搬参考插件的表格数据模型、刷新机制或内部模块导入方式
- 不为视觉效果增加无业务含义的图表
- 不在首页提供 API Key 编辑
- 不允许在“预览模型所见”中直接修改源数据
- 不承诺所有第三方 SillyTavern 主题像素级一致
