# 分层长程记忆

这是一个 SillyTavern 第三方扩展。它会在长时间聊天中自动整理人物状态、关系、约定、重要物品和剧情摘要，让模型在聊了很久以后仍然记得关键内容。

它不会在每次整理完成后刷新酒馆页面。整理失败时会保留任务、自动重试，并在记忆中心告诉你发生了什么。

在旧消息处使用 SillyTavern 的 Fork 创建剧情分支时，插件会在第一次继续生成前恢复分叉点当时的记忆。分叉点之后的事实、摘要和后台任务不会进入新分支，父分支和子分支随后独立保存。

- 仓库：https://github.com/124135417/sillytavern-layered-memory
- 协议：MIT
- 界面语言：中文

## 安装

1. 打开 SillyTavern 的扩展页面。
2. 选择“安装扩展”。
3. 粘贴下面的地址：

```text
https://github.com/124135417/sillytavern-layered-memory
```

4. 安装完成后，打开“分层长程记忆”。
5. 在设置中选择一个用来整理记忆的模型，点击“保存设置”，再用“测试连接”确认当前表单能正常访问模型。

安装后，酒馆顶部和扩展菜单中都会出现记忆中心入口。

## 它会记住什么

| 内容 | 作用 |
|---|---|
| 当前仍然成立的事实 | 记录人物状态、关系、约定、秘密、重要物品和世界变化 |
| 每轮发生的剧情 | 同一次后台整理生成一条简短剧情记录，包含用户输入、角色反应和结果 |
| 以前的剧情摘要 | 保存每轮、章节和长期剧情记录，并随当前记忆提供给主模型 |
| 与当前剧情相关的旧记忆 | 再次提到旧人物、地点或物品时，尝试找回相关剧情 |

你可以在“章节”中先看每章的关键事件，再按需展开完整摘要和对应的对话记录。底部入口会预览插件当前准备发送的剧情摘要、当前事实和相关旧记忆。

## 常用设置

- **记忆模型从哪里连接**：可以自己填写 API、密钥和模型，使用酒馆已保存的连接并另选模型，或明确跟随当前聊天模型。三种方式互不兜底，失败时不会偷偷换模型。
- **AI 正文提取规则**：可选。只把回复中的正文交给记忆模型；规则失配时会自动读取整条回复，不会漏记。
- **每多少轮整理一次剧情摘要**：推荐 25。
- **每多少轮自动检查一次记忆**：推荐 75。发现矛盾时会先请你确认。
- **需要时找回相关的旧记忆**：根据当前对话中的关键词寻找旧剧情，默认关闭。

选择“自己填写 API”后，模型服务地址、访问密钥和模型名称会直接显示在常用设置中，也可以读取服务商的模型列表。记忆容量和相关旧记忆的发送位置仍放在“高级设置”中。当前事实与剧情摘要都会进入主模型输入；有预设锚点时在预设指定位置展开，没有锚点时使用兼容系统提示。

## 与预设的前文回顾协作

如果角色预设已经用 `<前文回顾>...</前文回顾>` 包裹历史，请保留这些提示，并在回顾开头、Chat History 之前加入一行：

```text
{{layered_memory_context}}
```

这不是正则，也不依赖 Prompt Manager 中常见的 `order=100`。预设决定准确位置和宿主角色，插件只在该位置原地提供剧情摘要与当前承接状态。检测到一个启用锚点后，插件会自动关闭旧式 L1/L2 注入；没有锚点时继续兼容普通预设；出现多个启用锚点时不会重复展开，并会在记忆中心提示修正。

## 以前的聊天

插件默认从安装或首次启用之后开始记录，不会突然读取并改写整段旧聊天。

如果希望它重新整理以前的内容，请打开：

**记忆中心 → 对话记录**

安全重建会先备份现有结果，再把旧聊天按每约 12–13 组对话分段核对持久事实。“对话记录”和“章节”是两个独立页面、两项独立工作：先生成并检查对话记录，再由你决定何时生成章节。章节完成后对话记录仍然保留并可编辑，不会被章节替代。

从 v0.12.0 起，注入主模型的剧情连续性另按 SillyTavern **真实消息楼层**记账：用户消息和角色消息各是一楼，第 0–24 楼冻结为第一章，未满 25 楼的尾部逐楼完整注入。旧版按 user+assistant 配对保存的事实记录会保留，但不再冒充真实楼层；旧聊天会在后台批量补齐逐楼剧情摘要，补齐期间用有界原文临时兜底，因此不会先清空已有剧情。

从 v0.13.0 起，插件默认额外保留最近约 16,000 token 的连续完整楼层原文（按插件统一估算，可选 8,000 / 16,000 / 32,000），不读取或猜测服务商的真实上下文上限。现有逐楼后台调用会同时保存有原文证据的原子事件和楼内时间分段；一楼跨天时可以记录多个剧情时间变化。

两个页面分别显示自己的真实进度。对话记录页面按完成轮数计算；章节页面按完整章节数计算，并显示当前处理范围、剩余章节和不足一章的尾段。尾段只保留对话记录，不会被误当成完整章节。

章节摘要必须通过轮数覆盖和关键事件校验。建议字数不足时会重试一次；第二次仍较短但覆盖完整时会保存并标记“概述较精简”，不会因此让整次重建失败。任何真正的结构错误发生时，现有正式结果仍然保留，不会换上一半完成的数据。手动添加、钉住和人工编辑过的内容始终保留。

模型偶尔使用用户名代替内部用户标记时，插件会自动归一化。单条事实的引文不可靠时只会忽略该事实，不再连带丢弃整段剧情；如果某一轮摘要仍需修正，插件会保留同段内已经合格的轮次并只重试缺失轮次。最终结果未完整通过前仍不会替换旧记忆。

正式对话记录可以随时编辑。修改后只会把它所属的章节标为需要更新；点击“根据修改后的记录重新生成本章”只处理这一章，不会重新生成其他章节或对话记录。

重建工作会以较低优先级运行，不会挤掉最新对话的记忆整理。升级插件本身不会调用模型或产生 API 费用，只有点击“安全重建旧结果”后才开始。完成后建议检查一次“当前记忆”。

旧版中缺少主体、内容、原文证据或包含 `undefined` 的异常结果会移入隔离区。它们仍可供检查，但不会进入搜索、摘要索引或发送给模型。

## Fork 剧情分支

- 新分支会按消息的稳定标识继承分叉点以前的记忆，不会复制分叉点之后的剧情。
- 分支恢复期间，插件会阻止旧分支记忆进入生成请求。
- 如果父聊天无法读取，插件会清空旧记忆注入并显示“分支记忆恢复失败”，不会带着可能串线的内容继续。
- 插件会同时核对消息身份和实际正文；从另一条 swipe 分支时，不会误用原 swipe 的事实。
- 如果分支来自无法安全验证的旧版记录，插件不会冒险继承父表，而会从这个分支自己的历史重新整理。
- 父聊天从未使用本插件时，新分支会从当前末尾干净开始，不会误报恢复失败或自动产生大量补记请求。

“安全重建以前的聊天”会持续显示已完成轮数、总轮数、当前阶段和等待任务；刷新后状态仍会保留。停止会取消尚未执行的任务，当前正在请求模型的一项完成后安全停止，之后可以继续。

## 日常使用

- 插件可以全自动运行，不需要一直打开记忆中心。
- “当前记忆”展示现在仍然成立的重要内容。
- “对话记录”保留每轮发生的事情，并可独立编辑。
- “章节”按完整章节回顾以前发生过什么，并显示独立进度。
- “待处理”保存有冲突或需要你核对的建议；插件不会悄悄覆盖旧记忆。
- “记忆整理进度”展示正在处理、等待处理和需要重新处理的工作。
- 如果一条记忆有问题，可以点击旗帜按钮进行纠正。
- Alt + 右键某轮消息，也可以报告漏记问题。

插件会自己记录每轮剧情并生成章节摘要。建议关闭角色预设中的“每轮自动生成摘要”指令，以及只发送这些旧摘要的配套正则，避免主模型每轮重复花费输出 token。插件不会自动修改预设中的其它写作、状态或界面规则。

如果预设用 `<content>...</content>` 包裹正文，可以在设置中填写 `<content>([\s\S]*?)</content>`。留空时整条 AI 回复都作为正文；偶尔没有匹配也会自动回退整条回复。

## 隐私与连接

插件提供三种明确的连接方式：自己填写 OpenAI 兼容 API；使用酒馆已保存的连接（可临时覆盖模型名称）；跟随当前聊天模型。后台调用只走你选中的方式，不会在失败后自动改走另一条连接。

自己填写的访问密钥会保存在 SillyTavern 的设置文件中。插件不会在连接检查结果或问题记录中显示完整密钥。

## 已知限制

- 相关旧记忆目前主要依靠人物名、物品名、地点名等关键词寻找。完全没有提到关键词的隐性呼应可能找不到。
- 部分模型服务商不允许浏览器直接连接，此时“自己填写 API”可能无法使用，可以改用酒馆已保存的连接。
- 记忆容量是估算值，不同模型计算上下文用量的方式可能略有差异。
- 插件不估算最终上下文容量，也不裁剪 SillyTavern 准备发送的聊天历史。
- 继续生成、重新生成和角色代替用户发言时，插件会优先保留酒馆原有行为。
