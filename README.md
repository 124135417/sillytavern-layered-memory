# 分层长程记忆

这是一个 SillyTavern 第三方扩展。它会在长时间聊天中自动整理人物状态、关系、约定、重要物品和剧情摘要，让模型在聊了很久以后仍然记得关键内容。

它不会在每次整理完成后刷新酒馆页面。整理失败时会保留任务、自动重试，并在记忆中心告诉你发生了什么。

在旧消息处使用 SillyTavern 的 Fork 创建剧情分支时，插件会在第一次继续生成前恢复分叉点当时的记忆。分叉点之后的事实、摘要和后台任务不会进入新分支，父分支和子分支随后独立保存。

- 仓库：https://github.com/124135417/sillytavern-layered-memory
- 协议：MIT
- 界面语言：中文

## 安装

1. 打开 SillyTavern 的扩展页面。
2. 选择“安装扩展”。
3. 粘贴下面的地址：

```text
https://github.com/124135417/sillytavern-layered-memory
```

4. 安装完成后，打开“分层长程记忆”。
5. 在设置中选择一个用来整理记忆的模型，然后点击“保存并检查模型连接”。

安装后，酒馆顶部和扩展菜单中都会出现记忆中心入口。

## 它会记住什么

| 内容 | 作用 |
|---|---|
| 当前仍然成立的事实 | 记录人物状态、关系、约定、秘密、重要物品和世界变化 |
| 每轮发生的剧情 | 同一次后台整理生成一条简短剧情记录，包含用户输入、角色反应和结果 |
| 以前的剧情摘要 | 接替已经从本次请求中精简掉的较早聊天 |
| 最近剧情 | 先由当前预设和正则处理，再按上下文目标保留 |
| 与当前剧情相关的旧记忆 | 再次提到旧人物、地点或物品时，尝试找回相关剧情 |

你可以在“查看发送给模型的内容”中确认下一次回复会使用哪些记忆。

## 常用设置

- **记忆模型从哪里连接**：可以自己填写 API、密钥和模型，使用酒馆已保存的连接并另选模型，或明确跟随当前聊天模型。三种方式互不兜底，失败时不会偷偷换模型。
- **希望保留多少最近剧情**：默认“平衡”。插件会先尊重当前预设和正则的处理结果，再按上下文目标精简更早内容。
- **AI 正文提取规则**：可选。只把回复中的正文交给记忆模型；规则失配时会自动读取整条回复，不会漏记。
- **至少保留最近几轮完整对话**：推荐 6。即使空间紧张，这些对话也不会被插件精简。
- **每多少轮整理一次剧情摘要**：推荐 25。
- **每多少轮自动检查一次记忆**：推荐 75。发现矛盾时会先请你确认。
- **需要时找回相关的旧记忆**：根据当前对话中的关键词寻找旧剧情，默认关闭。

选择“自己填写 API”后，模型服务地址、访问密钥和模型名称会直接显示在常用设置中，也可以读取服务商的模型列表。记忆容量和发送位置仍放在“高级设置”中。

## 以前的聊天

插件默认从安装或首次启用之后开始记录，不会突然读取并改写整段旧聊天。

如果希望它整理以前的内容，请打开：

**设置 → 补记以前的聊天 → 开始补记旧聊天**

补记工作会以较低优先级运行，不会挤掉最新对话的记忆整理。完成后建议检查一次“当前记忆”。

## Fork 剧情分支

- 新分支会按消息的稳定标识继承分叉点以前的记忆，不会复制分叉点之后的剧情。
- 分支恢复期间，插件会阻止旧分支记忆进入生成请求。
- 如果父聊天无法读取，插件会清空旧记忆注入并显示“分支记忆恢复失败”，不会带着可能串线的内容继续。
- 插件会同时核对消息身份和实际正文；从另一条 swipe 分支时，不会误用原 swipe 的事实。
- 如果分支来自无法安全验证的旧版记录，插件不会冒险继承父表，而会从这个分支自己的历史重新整理。
- 父聊天从未使用本插件时，新分支会从当前末尾干净开始，不会误报恢复失败或自动产生大量补记请求。

“补记以前的聊天”会持续显示已完成轮数、总轮数、当前阶段和等待任务；刷新后状态仍会保留。停止会取消尚未执行的补记任务，当前正在请求模型的一项完成后安全停止，之后可以继续。

## 日常使用

- 插件可以全自动运行，不需要一直打开记忆中心。
- “当前记忆”展示现在仍然成立的重要内容。
- “剧情时间线”展示以前发生过什么。
- “待确认”保存有冲突或需要你决定的建议；插件不会悄悄覆盖旧记忆。
- “记忆整理进度”展示正在处理、等待处理和需要重新处理的工作。
- 如果一条记忆有问题，可以点击旗帜按钮进行纠正。
- Alt + 右键某轮消息，也可以报告漏记问题。

插件会自己记录每轮剧情并生成章节摘要。建议关闭角色预设中的“每轮自动生成摘要”指令，以及只发送这些旧摘要的配套正则，避免主模型每轮重复花费输出 token。插件不会自动修改预设中的其它写作、状态或界面规则。

如果预设用 `<content>...</content>` 包裹正文，可以在设置中填写 `<content>([\s\S]*?)</content>`。留空时整条 AI 回复都作为正文；偶尔没有匹配也会自动回退整条回复。

## 隐私与连接

插件提供三种明确的连接方式：自己填写 OpenAI 兼容 API；使用酒馆已保存的连接（可临时覆盖模型名称）；跟随当前聊天模型。后台调用只走你选中的方式，不会在失败后自动改走另一条连接。

自己填写的访问密钥会保存在 SillyTavern 的设置文件中。插件不会在连接检查结果或问题记录中显示完整密钥。

## 已知限制

- 相关旧记忆目前主要依靠人物名、物品名、地点名等关键词寻找。完全没有提到关键词的隐性呼应可能找不到。
- 部分模型服务商不允许浏览器直接连接，此时“自己填写 API”可能无法使用，可以改用酒馆已保存的连接。
- 记忆容量是估算值，不同模型计算上下文用量的方式可能略有差异。
- 插件设置的聊天历史目标只负责约束正则处理后的聊天部分；角色卡、预设、世界书和最终总上下文仍由 SillyTavern 统一计算。
- 继续生成、重新生成和角色代替用户发言时，插件会优先保留酒馆原有行为。
